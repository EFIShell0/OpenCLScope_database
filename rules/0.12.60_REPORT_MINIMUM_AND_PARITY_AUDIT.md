# 0.12.60 producer minimum and source-level design audit

Reference: pinned VulkanScope Database 1.4.12 design sheet (`assets/vulkan-layout.v1412.css`, `rules/UPSTREAM_REFERENCE_SITE_CSS.css`, `rules/UPSTREAM_REFERENCE_RULES.md`) and historical audited CSS/DOM inventories. Baseline: 0.12.59.

## Acceptance
- Previous Worker accepted explicitly enumerated app versions from 0.2.0 through 1.0.19. New Worker accepts *new submissions* exclusively from 1.0.19 / 10019 with matching native version and complete schema 1 evidence. Reject all earlier, unreviewed future, mismatched, imported, malformed and partial reports.
- Historical D1 report reading, snapshot and GET/list endpoints remain intact. The registry and query manifest remain immutable.

## Portable UI differences improved
- Semantic Compare previously used positional arrays (`platforms[0].devices[0].properties[17]`) and produced false differences under permuted enumerations. Comparison now uses platform/device identity, property token, extension name and image-format pair; distinct available/unknown/not_applicable/error values are preserved.
- Responsive Compare row and selection controls now use consistent container bounds, minimum touch height and mobile single-column labels, fitting existing reference-themed Settings, filter, pager, network banner and report cards.
- Stale public footer reported Database 0.12.56 and app range ending 1.0.16; corrected.
- CSS and JS assets newly versioned (v1260) to prevent stale browser caching after a UI release.

## Still not claimed
- Snapshot internals, regional settings and many supported UI controls already differ from Vulkan reference source structurally. OpenCL-specific sections necessarily differ.
- Browser screenshot/pixel tests and live Cloudflare deployment were not executed; do not label them PASS.

## Snapshot compatibility consequence
- The published-snapshot builder validates existing records via `validateStoredReport`, preserving the immutable per-version pre-1.0.19 query catalogs; POST always uses `validateSubmission` and rejects older producers. This separation is necessary to keep previously published legitimate reports visible without lifting the new submission ban.

- Statistics: added a portable Vulkan-style aggregate dashboard with report-backed bars for OpenCL vendor, API version and property status. It explicitly counts only downloaded complete reports and never treats unloaded reports or unavailable queries as supported.

- Overlay-checkout installation: `tools/reconcile_repository.py --apply` verifies and removes only known exact-hash retired producer-admission tests and obsolete `v1254` browser assets. Their original test content remains archived under `rules/history/pre_minimum_01259_worker_tests`; unknown edits fail safely.
