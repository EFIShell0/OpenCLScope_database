# Database 1.0.2: source-based VulkanScope 1.4.12 UI and Internet repair

Baseline OpenCLScope Database 1.0.1 and immutable VulkanScope Database 1.4.12. Page header and splash logo restored to the pre-1.0.1 OpenCLScope horizontal brand image; favicon uses Android OpenCLScope 1.0.19 `ic_opencl_tab.png` placed in a solid black square with no recoloring or cropped mark.

## Root causes
- Internet settings was only `navigator.onLine` and local diagnostics: the Worker had **no `/v1/network-info`** route. Imported upstream Cloudflare request-scoped projection and added bounded on-demand frontend read, masking addresses until Show. DNS resolver remains not observable; native reports cannot store IP fields. API config must point to deployed Worker, otherwise the page explicitly says unconfigured.
- Custom filter replacement creates a nested `.custom-select` wrapper, but page switch code was targeting `.parentElement` rather than `.closest(".filter-control")`; fixed. Added reported Device and Driver listboxes and actual report-summary filters.
- Logo regression in 1.0.1 used full app master for both site logo and favicon; now restored original horizontal wordmark and exact app OpenCL tab mark for the favicon.
- VulkanScope 1.4.12 table scrolling remains the reference source for existing table-scroll controls; current release does not claim full equivalence across unrelated OpenCL-only sections.

## Preservation
- Worker admission retains exact 1.0.19/10019 only for **new** submissions, historical stored reports GET remain accessible.
- Snapshot-first fetching and 16 platform + 210 device query gate unchanged.
- Network observations are request-scoped only, never written to D1 reports or saved in browser storage; second address family is only shown if provided by Cloudflare.

- Real Chromium test exposed an additional 1.0.1 listbox regression: VulkanSource CSS requires `.custom-select.open`; toggling only the `hidden` attribute left menu visibility hidden and opacity zero. Corrected both JS and CSS; actual click path verified on 1440/390/320.
- Worker `/v1/health` now reports true new upload floor 1.0.19 rather than historical 0.2.0.
